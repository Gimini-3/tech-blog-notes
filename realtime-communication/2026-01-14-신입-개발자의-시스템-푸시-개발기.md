## 시스템 푸시가 필요했던 이유

기존 푸시는 마케팅이나 콘텐츠 담당자가 Braze 대시보드에서 대상, 메시지, 콘텐츠와 발송 시간을 매번 설정하는 방식이었다. 단순한 조건은 대시보드에서 처리할 수 있지만, 사용자 행동 데이터나 사내 서버에만 있는 데이터를 이용한 세밀한 타기팅에는 한계가 있었다.

이를 해결하기 위해 타깃 사용자 선정부터 개인화된 콘텐츠 구성, 발송 예약까지 자동화하는 시스템 푸시를 개발했다. 예시는 같은 호텔 상세 페이지를 세 번 이상 본 사용자에게 해당 호텔 정보를 매일 오후 5시에 보내는 시나리오다.

## 시스템 푸시 처리 과정

전체 흐름은 다섯 단계로 구성된다.

1. Braze 대시보드에 API로 실행할 캠페인 템플릿을 만든다.
2. BigQuery에서 조건에 맞는 사용자와 콘텐츠를 조회한다.
3. 사용자별 제목, 메시지와 딥 링크를 구성한다.
4. Braze 스케줄링 API로 발송 시간을 예약한다.
5. cron으로 조회부터 예약까지의 작업을 주기적으로 반복한다.

Braze 템플릿에서는 Liquid 문법의 `api_trigger_properties`를 사용한다. 서버가 API를 호출할 때 사용자별 제목, 메시지와 딥 링크를 전달하면 하나의 캠페인 템플릿으로 개인화된 푸시를 만들 수 있다.

대상 데이터는 BigQuery에서 조회한 뒤 사용자별 발송 정보로 변환한다. 이후 Braze의 캠페인 스케줄링 API에 대상 목록과 예약 시간을 전달한다. 매일 보내야 하는 푸시는 실제 발송 시각 전에 cron 작업을 실행해 새로운 대상과 콘텐츠로 다시 예약한다.

## 결과와 운영상 주의점

원문에 따르면 다수 사용자에게 같은 내용을 보내던 기존 푸시의 오픈율은 약 2%였지만, 행동 데이터와 개인화 콘텐츠를 사용한 시스템 푸시는 평균 약 10%의 오픈율을 기록했다. 다만 이 수치는 캠페인의 대상 규모와 콘텐츠에 따라 달라질 수 있다.

푸시는 발송한 뒤 내용을 회수하거나 수정하기 어렵다. 따라서 대상 조회 조건, 개인화 변수, 발송 시간과 딥 링크를 실제 발송 전에 검증할 장치가 중요하다. 자동화는 반복 작업을 줄여 주지만, 잘못된 설정도 자동으로 대량 전파할 수 있기 때문이다.

## 느낀점

개인화 푸시는 메시지 문구만 바꾸는 기능이 아니라 데이터 조회, 템플릿 관리, 예약 실행과 외부 API 연동을 하나의 흐름으로 묶는 작업이라는 점이 인상 깊었다. 특히 자동 발송 시스템에서는 성공 경로뿐 아니라 잘못된 대상이나 콘텐츠가 발송되지 않도록 사전 검증과 모니터링을 함께 설계해야 한다고 느꼈다.
